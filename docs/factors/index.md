# The four factors

Each factor page follows the same structure:

- **Definition.** What the factor means.
- **What zero looks like.** The organizational behavior you'll see when this factor collapses.
- **Structural causes.** Why it collapses. These are almost always ownership, incentive, or architecture problems, not writing problems.
- **Diagnostic questions.** Things you can check this week to score the factor.
- **What moves it.** The interventions that change the score.

| Factor | Short definition | Most common structural cause of failure |
| --- | --- | --- |
| [Speed](./speed.md) | Time from question to usable answer | Knowledge spread across too many systems with no routing |
| [Clarity](./clarity.md) | Answer can be acted on without a follow-up | Content written for the author, not the reader |
| [Trust](./trust.md) | Answer is believed and acted on | No owner, no review date, no way to know it's current |
| [Reusability](./reusability.md) | Answer can be used again in another context | Knowledge locked inside one-off deliverables |

Read them in any order. If you already suspect where your constraint is, start there.
